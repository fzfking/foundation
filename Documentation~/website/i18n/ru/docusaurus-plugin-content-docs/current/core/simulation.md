# Симуляция

Симуляция выполняется с переменным или фиксированным шагом и не зависит от `FixedUpdate` Unity. Её можно
приостанавливать, возобновлять и ускорять через интерфейсы времени. UI только отображает состояние и не управляет
симуляцией.

Раннер продвигает игровую логику по времени кадра или явными шагами. Это не детерминированная симуляция, не
lockstep и не слой сетевой синхронизации; ограничения описаны в разделе [Ограничения](#limits).

| Тип | Роль |
| --- | --- |
| `ISimulationSystem` | Один фрагмент логики симуляции. `Order` сортирует системы; `Tick(in SimulationTick)` продвигает её. |
| `SimulationRunner` | Тикает все системы по порядку. `Start`, `Pause`, `Resume`, `Stop`, `Tick`, `Step`. |
| `SimulationTickMode` | `Automatic` по умолчанию. В режиме `Manual` симуляция продвигается только через `Step`. |
| `SimulationBacklogPolicy` | `Bounded` по умолчанию: ограниченная догонка, остаток учитывается как пропущенное время. `Preserve` сохраняет все невыполненные шаги для следующих кадров. |
| `SimulationTimers` | Таймеры в тиках симуляции; `Start` и `Stop` их очищают, а сработавшие таймеры выполняются после систем шага. |
| `ISimulationTimerHandle` | Отменяет один таймер через `Dispose`. |
| `ISimulationClock` | Сколько времени прошло с прошлого `Tick`. `TimeProviderSimulationClock` берёт нескалированное время кадра, умноженное на `ITimeController.SimulationScale`. |
| `SimulationTick` | То, что получает система: `Index`, `DeltaTime`, `ElapsedTime`. |
| `SimulationContext` | Состояние раннера: `State`, `TickIndex`, `ElapsedTime`, `DroppedTime`. |

Системы выполняются по возрастанию `Order`. При равном `Order` они сортируются по полному имени типа, а экземпляры
одного типа сохраняют порядок регистрации. Используйте одну систему на задачу, а не на сущность: не давайте каждой
строке производства или каждому врагу собственный `Update`.

## Пример {#example}

```csharp compile
using System.Threading;
using Cysharp.Threading.Tasks;
using Foundation.DI;
using Foundation.Lifecycle;
using Foundation.Simulation;
using Foundation.Timing;

public sealed class ProductionState
{
    public double Progress { get; set; }
}

public sealed class ProductionSystem : ISimulationSystem
{
    private readonly ProductionState _state;

    public ProductionSystem(ProductionState state) => _state = state;

    public int Order => 0;

    public void Tick(in SimulationTick tick) => _state.Progress += tick.DeltaTime;
}

public sealed class SimulationDriver : ITickableEntryPoint
{
    private readonly SimulationRunner _runner;

    public SimulationDriver(ProductionSystem production, ITimeProvider time, ITimeController timeController)
    {
        _runner = new SimulationRunner(
            new ISimulationSystem[] { production },
            new TimeProviderSimulationClock(time, timeController),
            fixedDeltaTime: 0.1f);
        _runner.Start();
    }

    public void Tick() => _runner.Tick();
}

public sealed class SimulationInstaller : IFeatureInstaller
{
    public void Install(IServiceRegistry registry)
    {
        registry.Register<ProductionState>(ServiceLifetime.Singleton);
        registry.Register<ProductionSystem>(ServiceLifetime.Singleton);
        registry.RegisterEntryPoint<SimulationDriver>();
    }
}
```

Зарегистрируйте `ITimeProvider` и `ITimeController` во внешней области DI-контейнера (см. [Время, планирование
и случайность](time-scheduling-random)).

## Автоматический и ручной режим {#automatic-and-manual}

Новый раннер находится в состоянии `Stopped`. `Start()` сбрасывает контекст и таймеры, затем переводит раннер в
`Running`. `Tick()` ничего не делает, если раннер не запущен или работает не в автоматическом режиме.

В режиме `Automatic` каждый `Tick()` продвигает симуляцию на `ISimulationClock.GetDeltaTime()`, а при заданном
`fixedDeltaTime` выполняет целые фиксированные шаги. `SimulationTicker`, который регистрирует `UseSimulation`,
вызывает `Start()`, а затем `Tick()` каждый кадр.

Для ручного управления передайте `tickMode: SimulationTickMode.Manual` и положительный `fixedDeltaTime`. В этом
режиме `Tick()` ничего не делает, а `Step(steps)` выполняет ровно указанное число целых фиксированных шагов (по
умолчанию один). Ручной режим подходит, когда моментом каждого шага управляет внешний lockstep-контроллер,
инструмент повтора или тест. В автоматическом режиме `Step()` бросает исключение. Пока раннер остановлен или стоит
на паузе, `Step()` ничего не делает; отрицательное число шагов отклоняется. Политика backlog к ручным шагам не
применяется.

## Фиксированные шаги, бюджет и догонка {#fixed-steps-budget-and-catch-up}

Если `fixedDeltaTime` не задан, каждый автоматический `Tick` продвигает симуляцию на дельту времени. Если задан,
за один кадр выполняются целые фиксированные шаги, но не больше `MaxStepsPerTick` (по умолчанию 8).

Время, оставшееся после этого бюджета, обрабатывается по `BacklogPolicy`:

- `Bounded` (по умолчанию): в следующие кадры переносится не больше `MaxCatchUpTime` времени симуляции. Остаток
  пропускается и добавляется в `SimulationContext.DroppedTime`, чтобы отставание было видно. При
  `MaxCatchUpTime` по умолчанию, равном нулю, время сверх бюджета шагов пропускается, а не переносится дальше.
- `Preserve`: все невыполненные целые шаги остаются в аккумуляторе и выполняются в следующих кадрах, но не больше
  `MaxStepsPerTick` за кадр. В `DroppedTime` ничего не добавляется. Если симуляция не успевает за часами, очередь
  растёт без ограничения.

| Игра | Настройка |
| --- | --- |
| Экшен | Оставьте значения по умолчанию: время сверх бюджета шагов за кадр пропускается. |
| Игра с ускорением | Поднимите `maxStepsPerTick` до числа шагов, которое нужно на кадр при максимальной скорости (x5 при 20 fps и шаге 1/60 с требует 15). |
| Симуляция, которая не должна терять время (симулятор колонии) | Используйте `SimulationBacklogPolicy.Preserve`. При `Bounded` время сверх `maxCatchUpTime` отбрасывается. |

## Таймеры симуляции {#simulation-timers}

Таймеры доступны через `runner.Timers` или как сервис `SimulationTimers` из области, где вызван `UseSimulation`.
Задержка считается в целых тиках симуляции, а не в секундах: при фиксированном шаге один шаг равен одному тику,
без него каждый `Tick()` равен одному тику.

`Schedule(delayTicks, callback)` с нулевой задержкой выполняется на следующем тике. Таймер, запланированный во
время тика, не срабатывает в этом же тике. Таймеры, срок которых наступил в одном тике, выполняются в порядке
планирования, а все сработавшие таймеры идут после систем шага. Если номер тика срабатывания выходит за границы
счётчика, планирование отклоняется.

`Dispose` дескриптора отменяет один таймер. `Clear()` отменяет все таймеры, включая уже готовые к выполнению в
текущем шаге. `Start()` и `Stop()` очищают таймеры так же, поэтому ни один таймер не переживает запуск. Таймер,
запланированный до `Start()`, будет отброшен этим запуском; планируйте после запуска или из первого тика системы.
Пауза сохраняет таймеры, а возобновление продолжает их отсчёт тиков.

Таймеры не сериализуются: раннер не сохраняет и не восстанавливает колбэки. Если игра сохраняет события, она
должна запланировать их заново после каждого запуска.

## Порядок, пауза и остановка {#order-pause-stop}

Один шаг выполняет системы в описанном выше порядке, затем таймеры, срок которых наступил в этом тике. Колбэки
обоих видов могут вызывать `Pause`, `Resume`, `Stop` и `Start`.

`Pause` из колбэка даёт текущему шагу завершиться, фиксирует его `TickIndex` и останавливает остаток пакета.
`Resume`, вызванный позже в этом же шаге, возвращает состояние `Running`, но не перезапускает пакет. Время,
проведённое на паузе, после `Resume` не проигрывается.

`Stop` сбрасывает контекст к нулевому `TickIndex` и очищает таймеры. Из колбэка он немедленно прерывает шаг: ни одна
система или таймер этого шага больше не выполняется, и приращение `TickIndex` после сброса не происходит. `Start`
также сбрасывает контекст и очищает таймеры перед запуском.

Вызов `Tick` или `Step` из колбэка системы или таймера бросает `InvalidOperationException`: раннер не может
продвигаться изнутри собственного шага. `Pause`, `Resume`, `Start` и `Stop` из колбэка разрешены.

Запуск останавливает только исключение из системы или таймера. Ошибка пробрасывается вызывающему коду, а раннер
не откатывает состояние игры, поэтому перед новым запуском игра должна восстановить частично изменённые данные.
Исключение из `ISimulationClock` или недопустимая дельта часов (NaN или бесконечность) пробрасываются без
изменения состояния раннера.

## Пауза и скорость {#pausing-and-speed}

`SimulationRunner.Pause()` и `Resume()` останавливают и возобновляют тики, не сбрасывая состояние; `Stop()`
сбрасывает контекст и таймеры. `ITimeController.SetSimulationScale(2f)` удваивает скорость, которую сообщают
часы; `0` замораживает их, не трогая время анимации (`SetAnimationScale` меняет `timeScale` Unity).

## Ограничения {#limits}

`TimeProviderSimulationClock` сообщает нескалированное время кадра, умноженное на
`ITimeController.SimulationScale`, поэтому симуляция следует за временем кадра. Это не делает игру
детерминированной. В раннере нет захвата ввода, отката, хеширования состояния, lockstep или сетевой
синхронизации, и он не обещает стабильную физику при разной частоте кадров или на разных устройствах.
`DeterministicRandomService` делает воспроизводимой последовательность случайных чисел. Для детерминированной
игры этого недостаточно.

Для повтора или lockstep-игры используйте ручной режим, фиксированные шаги и собственный захват ввода и
состояния. Раннер даёт упорядоченные шаги и таймеры в тиках, всё остальное остаётся за игрой.
