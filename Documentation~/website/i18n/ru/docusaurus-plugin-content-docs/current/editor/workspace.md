# Рабочая область контента

**Content → Content Workspace** — окно редактора для просмотра и правки исходников игровых данных, а также для
их проверки и сборки. Оно находится в редакторной сборке контента (`Foundation.Content.Editor`), не ссылается
на код конкретной игры и построено на Unity UI Toolkit. Проект, которому нужен другой интерфейс редактора,
может заменить его представление через `ContentWorkspaceWindow.PresentationFactory`.

## Подстраивается под ваш проект {#it-adapts-to-your-project}

Окно вызывает `ConfigBuildEntryPoint.BuilderFactory().DiscoverSources()`, поэтому видит те же источники и
зарегистрированные провайдеры, что и ваш конвейер сборки (см. [Конфиги](../app/config#build-time-pipeline)).
Отдельный реестр контента не нужен.

Для исходных ассетов Unity, реализующих `IConfigAuthoringSource` (контракт из `Foundation.Content.Authoring`):

- Сериализуемые массивы и списки верхнего уровня автоматически становятся группами, в том числе пустые
  коллекции.
- Остальные видимые сериализуемые поля, включая унаследованные, показываются в **Settings**.
- Прямые поля записей становятся столбцами таблицы; вложенные данные редактируются в панели деталей.
- Поле с именем `Id` (без учёта регистра, включая скрытое поле автосвойства) подписывает записи и позволяет по
  возможности переходить к записи из ошибок проверки. Это соглашение, а не схема.
- Поиск сопоставляется со всеми показанными значениями и требует совпадения всех слов, разделённых пробелами.
- **Add** создаёт запись по умолчанию, **Duplicate** делает сериализованную копию, **Delete** удаляет запись.
  Коллекции абстрактных или полиморфных элементов могут начинаться с пустого слота; конкретный тип выбирается
  в редакторе деталей. Для Add у конкретных записей нужен конструктор без параметров.
- Duplicate сохраняет исходный идентификатор. Назначьте новый до проверки или сборки.
- Правки идут через сериализацию Unity и Undo. **Save source** сохраняет только выбранный источник. Сборки
  используют исходные данные из памяти, но не сохраняют ассеты неявно.

## Источники на основе файлов {#file-backed-sources}

Источник, опирающийся на файл, реализует `IContentWorkspaceFileSource`, который отдаёт канонические пути и
форматы независимо от экспортёров и сгенерированных бинарных файлов.

- Локализация показывает свой настоящий CSV как одну группу: ключ, контекст и каждый авторский столбец локали
  видны и редактируются.
- Источники туториала показывают каждый исходный `.txt` как группу с полноценным многострочным редактором
  сценария.
- **Open source file** открывает канонический файл; **Reload file** перечитывает его, спрашивая перед
  отбрасыванием изменённого черновика.
- Сохранение CSV корректно экранирует ячейки, сохраняет переводы строк внутри ячеек и все авторские столбцы и
  пишет UTF-8. Перед сохранением окно проверяет, не был ли исходный файл изменён или удалён, и блокирует запись, если
  обнаруживает различие. Версия файла, изменённая другим процессом между последней проверкой и заменой, всё ещё
  может быть перезаписана.
- Если при разборе CSV обнаружены ошибки или строка содержит больше полей, чем заголовок, окно показывает
  диагностику и блокирует редактирование и сохранение. Исправьте файл вне окна и нажмите **Reload file**.
- Черновики остаются доступными при переключении источников и перезагрузке сборок редактора, с Undo Unity. При
  закрытии окна для несохранённых черновиков файлов используется стандартный запрос Unity «сохранить или
  отбросить».
- **Validate** и **Build** требуют сохранённых черновиков файлов, потому что конвейер читает канонические
  файлы.

Другие обычные C#-провайдеры могут реализовать тот же интерфейс, чтобы показывать CSV или текстовые исходники.
Провайдер без представления исходных данных показывает пояснение; экспортированные файлы `.bytes` никогда не
используются как представление исходника.

## Проверка и сборка {#validate-and-build}

**Validate all** вызывает `ConfigBuilder.Validate`: экспорт и проверку без бинарной сериализации, записи
файлов и постобработчиков. Поэтому экспортёры и валидаторы должны быть без побочных эффектов. **Build all**
использует обычный поток `ConfigBuilder.Build`.

По ошибке проверки можно перейти к источнику и к соответствующей записи, если её можно определить по `Source`
и `EntryId`. Ошибки без идентификаторов записей находят только источник. Если имена или идентификаторы
неоднозначны, выбирается первый подходящий источник или группа.

## Интеграция в проект {#integrating-a-project}

Сохраните существующую композицию `BuilderFactory`, экспортёры, валидаторы и постобработчики. Добавление
сериализуемой коллекции в существующий источник не требует регистрации в окне. Новому источнику нужен
`IConfigAuthoringSource` и та же регистрация экспортёра и валидатора, что требует `ConfigBuilder`.

## Чего оно не делает {#what-it-does-not-do}

Здесь нет редактирования графов и симуляции баланса. Окно не определяет связи игровых данных по произвольным
строковым полям; для этого нужны настоящие контракты проекта, а не догадки по именам полей.
