# Зеркала контента

Foundation может направлять запросы за удалённым контентом через настроенные зеркала и выбирать порядок по
измеренной пропускной способности. Зеркала настраивает проект: Foundation не задаёт CDN-адреса, не загружает и не
копирует файлы между хостами и не проверяет, что разные источники содержат одинаковые данные.

Общая политика находится в `Foundation.ContentMirroring`. Unity-адаптер `Foundation.Infrastructure.ContentMirroring`
предоставляет проверку через `UnityWebRequest` и хранилище статистики на `PlayerPrefs`.

## Настройка

Для каждого источника создайте `ContentMirror` со стабильным ID и абсолютным HTTP(S)-адресом. ID используется как ключ
сохранённых измерений скорости, поэтому не меняйте его, пока источник остаётся тем же. Проект также должен разместить
на каждом зеркале небольшой файл по относительному пути `ProbePath`. Unity-проверка скачивает файл методом GET и
принимает его только при успешном ответе и совпадении фактического размера с заданным.

```csharp
var mirrors = new[]
{
    new ContentMirror("edge-a", "https://edge-a.example/content"),
    new ContentMirror("edge-b", "https://edge-b.example/content"),
};

var configuration = new ContentMirrorConfiguration(
    mirrors,
    probePath: "mirror-probe.bin",
    probeSizeBytes: 262144,
    maximumEta: TimeSpan.FromSeconds(30),
    statisticsLifetime: TimeSpan.FromHours(24));

var coordinator = new ContentMirrorCoordinator(
    configuration,
    new UnityWebRequestContentMirrorProbe(),
    new PlayerPrefsContentMirrorStatisticsStore());
```

Если зеркало использует query-параметры для авторизации, передайте необязательный синхронный `queryProvider` в
`ContentMirror`. Он получает итоговый абсолютный URI с уже собранным путём и возвращает query-параметры с `?` или без
него. Provider применяется к URL проверки, YooAsset и Addressables. Статические query-параметры базового URL также
сохраняются; fragment запрещён, поскольку он не отправляется в HTTP-запросе.

```csharp
var mirror = new ContentMirror(
    "signed-edge",
    "https://edge.example/content",
    queryProvider: uri => "token=" + Uri.EscapeDataString(GetTokenFor(uri)));
```

Необязательно передать конструктору координатора `preferredMirrorId` и `preferredMirrorMaximumEta`: тогда
предпочтительное зеркало будет первым, если расчётное время загрузки укладывается в этот предел. Последнее успешное
зеркало в процессе имеет приоритет над предпочтительным.

Координатор выполняет операции последовательно и при каждом вызове `ExecuteAsync` заново проверяет все зеркала,
кроме явно исключённого базового URL.
Сохранённое измерение скорости не пропускает проверку: оно может влиять только на порядок зеркал, чья свежая проверка
успешна, а успешная проверка заменяет сохранённое значение. Зеркало, которое последним завершило попытку успешно,
остаётся первым при следующих вызовах в том же процессе, если конфигурация повторно использует тот же экземпляр
`ContentMirror`. Это состояние хранится только в памяти и сбрасывается при
перезапуске процесса. Прогресс помогает оценить оставшееся время. Если превышен `MaximumEta`, координатор отменяет
токен попытки и переходит к следующему кандидату после её завершения. Адаптер Addressables перед сменой зеркала
дожидается завершения текущей операции: так он не прерывает независимую загрузку, которая использует тот же URL.
Отмена токена вызывающего кода завершает ожидание и освобождает handle операции; уже начатая загрузка Addressables
может завершиться в фоне. Если предел ETA превышен для всех кандидатов, координатор один раз повторяет попытку через
первое зеркало в рейтинге скорости без ограничения ETA. Рейтинг фиксируется до применения sticky и предпочтительного
зеркала. Все кандидаты должны пройти свежую проверку, но для рейтинга может использоваться сохранённая скорость. Если
ни одна попытка не завершилась успешно, координатор
возвращает `false`, если только сама попытка не выбросила исключение. Вызывающий код возвращает маршрут к настроенному
базовому адресу (endpoint Addressables или remote URL YooAsset). Addressables после этого продолжает повторять через
`WaitingForConnection`, а YooAsset может остаться на пригодной локальной версии. Неудачная проверка не доказывает,
что сеть недоступна или что на зеркале нет остального контента: она означает только, что проверочный файл не ответил
как ожидалось.

По умолчанию проверки зеркал выполняются последовательно. Передайте `parallelProbes: true` последним аргументом
`ContentMirrorConfiguration`, чтобы запустить их одновременно и дождаться всех результатов перед выбором зеркала.
В этом режиме собственная реализация `IContentMirrorProbe` должна поддерживать одновременные вызовы. Запросы делят
пропускную способность сети, поэтому измеренная скорость может отличаться от последовательной проверки. Параметр
`timeoutSeconds` Unity-проверки ограничивает каждый запрос отдельно.

У `AnyContentHostReachabilityChecker` в Addressables есть независимая опция `parallelChecks`. По умолчанию проверки
последовательные; `new AnyContentHostReachabilityChecker(probeUrls, timeoutSeconds: 2, parallelChecks: true)` запускает
HEAD-запросы одновременно и отменяет остальные после ответа одного из хостов. Таймаут применяется к каждому
HEAD-запросу, а не к последующей проверке зеркал или загрузке контента.

`PlayerPrefsContentMirrorStatisticsStore` сохраняет измерения байт в секунду по ID зеркала. Если проекту нужна другая
политика хранения, используйте собственную реализацию `IContentMirrorStatisticsStore`. Сохранённые скорости не решают,
проверять ли зеркало, и не хранят последнее успешное зеркало.

## Интеграции {#integrations}

- **Addressables:** для стратегии offline-first передайте координатор в `ContentStartupBootStep` или
  `AddressablesContentSynchronizer`. При запуске адаптер проверяет файлы каталога на release endpoint и один раз
  пытается обновить каталог, если они доступны. Затем попытки загрузки bundle идут через выбранные зеркала без
  дублирования общего пути content root в URL. Успешная предварительная проверка не гарантирует успех следующего
  запроса каталога. При отмене попытки адаптер не вызывает глобальный Abort:
  независимые загрузки могут использовать тот же URL зеркала. В режиме зеркал синхронизатор спрашивает у
  `IContentHostReachabilityChecker` только одно: сообщает ли устройство об отсутствии сети
  (`INetworkReachabilityStatusProvider.IsNetworkUnavailable`). `NotReachable` — единственный жёсткий признак офлайна;
  неудачная проверка отдельного хоста сама по себе ничего не доказывает и не останавливает проход по зеркалам.
  `AnyContentHostReachabilityChecker` сообщает об офлайне, только когда об этом сообщают все настроенные хосты; он
  удобен, когда одна проверка покрывает несколько хостов. Без координатора остаётся прежний режим с одним endpoint. См.
  [Addressables](../adapters/addressables).
- **YooAsset:** передайте координатор в `YooAssetContentSynchronizer`; инициализатор применяет выбранное зеркало к
  удалённому сервису. После неудачного прохода callback `applyMirror` получает `null`, чтобы вернуть основной URL.
  На зеркалах должны совпадать версия пакета, манифест и пути bundle. См. [YooAsset](../adapters/yooasset).
- **HybridCLR:** `MirroredHotUpdateAssemblySource` может повторить загрузку одного адреса сборки через другое зеркало,
  если загрузка или проверка подписи завершилась ошибкой. Ему нужны verifier, маршрутизация зеркал и callbacks для
  очистки кэша/проверки размера загрузки; стандартный `HybridClrGameModuleLoader` не использует его, пока источник
  не передан явно. Когда проход по альтернативным зеркалам возвращает `false`, callback маршрутизации получает `null`,
  чтобы восстановить исходный маршрут. Ошибки или отмена до этого обрабатываются как исключения. См.
  [Игровые модули](game-modules#hot-update-with-hybridclr).

Зеркала обеспечивают маршрутизацию и повторы, но не целостность контента и не подлинность исполняемого кода. Содержимое
зеркал должно соответствовать выбранному каталогу/пакету; для сборок горячего обновления используйте проверку подписи.
Группы и режим упаковки Addressables остаются настройкой проекта — для зеркал менять их не требуется.
